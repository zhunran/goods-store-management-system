# 商品商城管理系统 — 架构

> 文档状态：项目完成态描述（预设完成视角，运行态收口项于交付前完成）。

## 一、总体架构

采用微服务分层架构，请求链路如下：

```
浏览器（前端 SPA：admin-web 管理端 / owner-web 用户端）
    │
    ▼
Spring Cloud Gateway（8888，响应式 WebFlux，统一鉴权/路由）
    │
    ├── /app/api/** ──────► goods-store-web（BFF 聚合层，8090）
    │                          │ Feign
    │                          ▼
    │               ┌──────────┴──────────┐
    │               │ auth / brand / product / member / trade / seckill
    │               └─────────────────────┘
    └── /auth|brand|good|member|trade|seckill/api/** ──► 各业务服务直连
                              │
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
           MySQL           Redis            RabbitMQ
        （数据存储）    （缓存/分布式锁）    （异步消息）
```

## 二、模块清单与端口

| 模块                    | 类型       | 端口 | 说明                                        |
| ----------------------- | ---------- | ---- | ------------------------------------------- |
| goods-store-gateway     | 网关       | 8888 | 统一入口、JWT 鉴权、路由转发、Sentinel 限流 |
| goods-store-web         | BFF 聚合层 | 8090 | 聚合各服务接口，供前端 `/app/api/**` 调用   |
| goods-store-auth-api    | 业务服务   | 8083 | 认证 / 权限                                 |
| goods-store-brand-api   | 业务服务   | 8081 | 品牌                                        |
| goods-store-product-api | 业务服务   | 8084 | 商品 / 分类 / SKU                           |
| goods-store-member-api  | 业务服务   | 8085 | 会员 / 地址                                 |
| goods-store-trade-api   | 业务服务   | 8086 | 购物车 / 订单                               |
| goods-store-seckill-api | 业务服务   | 8087 | 秒杀                                        |
| goods-store-spi         | 契约层     | —    | Feign 接口契约 + DTO/VO                     |
| goods-store-common      | 公共层     | —    | 通用返回、异常、工具、消息模型              |

## 三、服务调用与契约（SPI 模式）

- 服务间调用通过 `goods-store-spi` 下的各 `*-spi` 契约模块定义接口与 DTO，避免服务间直接依赖实现类
- BFF 层通过 Feign 客户端聚合调用各业务服务
- 跨服务调用（Feign）：
  - product → brand（含降级 FallbackFactory）
  - trade → member、product
  - seckill → product、member
- Feign 请求头透传（FeignTraceInterceptor / TradeFeignHeaderInterceptor）保证 TraceId 与登录信息在服务间传递

## 四、网关路由规则

| 路由              | 目标服务                | 说明                                     |
| ----------------- | ----------------------- | ---------------------------------------- |
| `/app/api/**`     | goods-store-web         | 前端唯一入口（BFF）                      |
| `/auth/api/**`    | goods-store-auth-api    | 认证服务                                 |
| `/brand/api/**`   | goods-store-brand-api   | 品牌服务                                 |
| `/good/api/**`    | goods-store-product-api | 商品服务（控制器实际前缀为 `/good/api`） |
| `/member/api/**`  | goods-store-member-api  | 会员服务                                 |
| `/trade/api/**`   | goods-store-trade-api   | 交易服务                                 |
| `/seckill/api/**` | goods-store-seckill-api | 秒杀服务                                 |

## 五、关键设计

- **统一鉴权**：JWT 双令牌，网关校验签名，BFF 登录接口豁免拦截（AdminWebMvcConfig）
- **分布式主键**：雪花算法 SnowflakeUtil，各服务分配不同 worker-id（1~7）
- **配置中心**：Nacos 统一配置（`goods-store-common.yaml`、`goods-store-shared-service-config.yaml` 及各服务专属配置）
- **服务注册与发现**：Nacos（默认账密 nacos/nacos，group DEFAULT_GROUP）
- **熔断限流**：Sentinel（Dashboard 8080，网关与服务均接入）
- **异步解耦**：RabbitMQ（下单、取消订单、秒杀下单消息）
- **支付状态机**：订单六态（10 待付款 / 20 已支付 / 30 已发货 / 40 已完成 / 50 已取消 / 60 已退款），模拟支付/退款以 CAS 条件更新 + `pay_log` 流水表保证幂等，与 30 分钟超时取消以「非 PENDING 即跳过」的竞争语义协调
- **分布式锁**：Redisson（下单防重、秒杀扣库存）
- **链路追踪**：SkyWalking Agent + TraceId 透传（TraceIdWebFilter / FeignTraceInterceptor）
